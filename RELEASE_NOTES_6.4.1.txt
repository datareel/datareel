DataReel 6.4.1 Release Notes, 11/17/2026
DataReel version 6.4.1 (was 6.4)
DataReel Copyright (c) 2001-2026 DataReel Software Development

DataReel 6.4.1 is a bug-fix release of DataReel 6.4: socket and thread
fixes only. The API, the database file format and the gxStream wire
format are the same as 6.4, and everything in RELEASE_NOTES_6.4.txt is
included. Version 6 is the legacy line: it gets bug fixes and security
updates, but no new features. The shared library (Linux makefiles) is
built as libdatareel.so.6.4.1.

FIXES
-----
- gxSocket: close-on-exec sockets: gxSocket::Socket() and both
  gxSocket::Accept() calls set FD_CLOEXEC (POSIX). A program that forks
  and runs other programs used to pass them its sockets; a child that
  kept a server's listening socket held the port open, so a restarted
  server could not bind it. (DRCM 1.46 carried this change in its own
  copy of gxsocket.cpp.) Test: examples_socket/socket_security, the
  "cloexec" check.
- Threads: state set before the thread starts: apiCreateThread() (POSIX)
  sets the thread state to RUNNING before pthread_create(). The new
  thread used to set it itself, so a caller could see NEW right after
  CreateThread() and take the thread for one that never ran, and a
  cancel made before the thread ran had CANCELED overwritten with
  RUNNING.
- Threads: monotonic timed waits: On Linux, condition variables use
  CLOCK_MONOTONIC and gxThreadConditionTimedWait() computes its deadline
  on it. A change to the system time (an NTP step, date -s) used to make
  timed waits end early or last hours longer.
- Threads: sleep functions: api_nSleep(), api_uSleep() and api_mSleep()
  locked a mutex, never unlocked it and destroyed it locked on every
  call, and uSleep() overflowed on 32-bit systems. They now use
  nanosleep() (POSIX) or Sleep() (Windows). Test:
  examples_threads/thread_security (state, cancel, sleep, timedwait).
