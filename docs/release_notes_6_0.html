DataReel 6.0 Release Notes

DataReel 6.0 Release Notes, 10/24/2026

DataReel version 6.0 (was 5.10)

DataReel 6.0 is the first major release in many years. Version 5.10, tagged 5.10 in the repository, is the last version 5 release.

Version 6.0 fixes every item listed under "Known Items Left As Is" in CODE_REVIEW_FIXES.txt. Those items were held back in 5.10 because they needed a new interface or would change existing files. Every change in the source is marked with a "10/24/2026" comment. The changes were made by Claude Code, Anthropic's AI coding assistant (https://claude.ai/code).

The library version in version.txt is 6.0 and the shared library version (SHAREDLIB_VERSION in env/linux.env) is 6.0, so the Linux shared library is built as libdatareel.so.6.0. Programs must be recompiled against the 6.0 headers. Some classes gained members and some function signatures changed (see Upgrading From Version 5).

How the Changes Were Tested

  • The library and the OpenSSL library build with no warnings using GCC 13 with -Wall -Wextra, at -O0 and at -O2.
  • The 39 database, general and thread example programs were built with AddressSanitizer and UndefinedBehaviorSanitizer and run with no reports.
  • New test programs for each change pass against 6.0. The RDBMS, XML and thread pool tests fail against 5.10, which shows that they test the problems that were fixed. The glibc mutex problem was reproduced with a small C program: after a trylock that returns ENOTRECOVERABLE, an unlock crashes and a lock never returns.

Linked Lists

  • New gxList::DestroyArrayList() and gxListB::DestroyArrayList() free each item with delete[], for strings and other data allocated with new[]. DestroyList() still uses a scalar delete and is only for data allocated with a single object new.
  • examples_general/doubly_linked_list uses DestroyArrayList().

Configuration Manager

  • gxConfig::Add(const gxString &) hid the virtual gxListB::Add(void *) (-Woverloaded-virtual). gxConfig now overrides Add(void *) as a private function that adds nothing and returns a null value, since every node in a configuration list must hold a gxString.
  • New gxConfig::Add(const char *), so Add(char_buffer) stores the text as a string instead of picking the void pointer overload.

Thread Pool

  • thrPool::ClearPool() and the thrPool destructor used to delete every thread with a plain delete, even while it was still running. They now cancel running, suspended and waiting joinable threads and, under POSIX, wait for them to finish before deleting them.
  • gxThread::DestroyThreadPool() and gxThread::DestroyThread() with check_state also wait for a canceled thread under POSIX. pthread_cancel() only sends a cancel request, so a canceled thread could still be running when its gxThread_t was deleted.
  • New gxThreadAPIWrapper::apiStopThread() cancels a thread and waits for it.
  • A canceled thread stops at its next cancellation point. A thread that never reaches one keeps these functions waiting. A canceled thread runs gxThread::ThreadCleanupHandler(), so the gxThread object must still exist when the pool is cleared. Detached threads cannot be canceled and are still deleted without being stopped.

Database File Cache

  • gxDBCacheNode::Bind() loaded a segment that was not in the cache with a read length of one byte. The cache node now remembers the length of its last CachedRead(), CachedWrite() or Bind(bytes) call and loads the whole node. With no length set, only a segment that is already cached is bound, and the node address is kept.
  • New gxDBCacheNode::Bind(bytes), GetNodeLength() and SetNodeLength().
  • gxDatabaseCache::ReleaseSegments() now returns the segment array and leaves the cache empty. It used to set only the array pointer to null, so the head and tail still pointed into the released array. The caller frees the returned array with delete[].

Relational Database

  • ALLOWDUP lookups by key: with duplicates allowed the block address is part of each B-tree key, so a search key with a block address of 0 never matched. FindRecord(), DeleteRecord() and the change functions could not find any record through an index. Find() now starts at the first key with the same CRC-32 value and reads each record with that value until one matches.
  • AddRecord() no longer checks for an existing key when duplicates are allowed. The check always passed before, because the lookup always failed.
  • BLOB fields in all-field keys: CreateKey() moved its write offset past a BLOB field but did not count it in the key length, so the fields after a BLOB were left out of the key. BLOB fields are now skipped without leaving a gap.
  • File change: the all-field keys of tables with BLOB fields are different in 6.0. Rebuild the index files of those tables with RebuildIndex after upgrading. Index files of other tables do not change.

XML Parser

  • Text mixed with child elements is kept in document order. It used to be dropped. Inside a parent, child or sub-element, each piece of text is stored as a node with an empty name and the text in its data member. Text between the parent elements of the root is stored in node_tree with the new node type gxsXML_TEXT_NODE and passed to Handle_Parent_Event() in SAX mode.
  • Leading and trailing white space is removed from the text, and text that is only white space is not kept, so a document written and loaded again gives the same tree.
  • The writer writes a node with no name as text.
  • Code that walks a loaded tree will see the text nodes in documents with mixed content, and should skip nodes with an empty name if it only wants elements.

RSS Feed Writer

  • New gxRSScloud structure with domain, port, path, registerprocedure and protocol members. gxRSSchannel::cloud is now a gxRSScloud (it was a gxString).
  • The <cloud> element is written as an empty element with the five attributes the RSS 2.0 specification requires, when cloud.domain is set. It used to be written as element text, which is not valid RSS.

Thread Helpers and glibc

  • In glibc 2.39 a pthread_mutex_trylock() call that returns ENOTRECOVERABLE on a robust mutex leaves the mutex in a bad state: a later unlock crashes and a later lock never returns.
  • gxMutex_t has a new not_recoverable member. It is set when gxThreadMutexLock() or gxThreadMutexTryLock() gets ENOTRECOVERABLE. The lock, try lock and unlock functions then return ENOTRECOVERABLE and store gxMUTEX_NOTRECOVERABLE_ERROR without calling glibc, and gxThreadMutexDestroy() skips its unlock call. The mutex can be destroyed and initialized again.

Compiler Warnings

With -Wall -Wextra the 5.10 library reported warnings at 117 places in the source. All are fixed:

  • The private copy constructors and assignment operators used to disallow copying no longer name their unused parameter. The parameters of other functions that are not used are commented out, or marked with (void) where only WIN32 builds use them.
  • "operator const int () const" is now "operator int () const", and gxDatabase::GetRevLetter() returns char.
  • Casts to "const unsigned char" in htmldrv.cpp and ostrbase.cpp are now casts to unsigned char.
  • HyperText::TableHeader() and TableData() take a const char *valign, and PostScriptDrv::SetDocumentName() keeps a const char pointer, so string literals can be passed without a cast.
  • Signed and unsigned compares in gxdatagm.cpp, gxstream.cpp, scomserv.cpp and gxrdbhdr.cpp.
  • gxBStree::Find() had an unused variable.

Other Fixes

Found while testing the changes above:

  • DiskFileB::df_copy() stored the file lengths in unsigned variables, so the tests for a futils_filelength() error could never be true.
  • gxDatabase::ReadObjectChecksum() compared CRC values that were never set when the file was not open. It now returns 0. The optional CRC pointers are checked for null on every path.
  • ASPrint() for int, long and double values formatted the number into a buffer the size of the field width, which overflowed for a narrow field. long values were truncated to int. A fixed buffer and snprintf() are used now.
  • operator>>() for UString and UStringw read an uninitialized buffer when the input failed, for example at the end of the input. Found by AddressSanitizer in examples_general/string_class.

Upgrading From Version 5

  • Recompile every program against the 6.0 headers and link with the 6.0 library.
  • gxRSSchannel::cloud is a gxRSScloud. Set cloud.domain, cloud.port, cloud.path, cloud.registerprocedure and cloud.protocol instead of assigning a string.
  • gxDatabaseCache::ReleaseSegments() returns the segment array. Free it with delete[] when it is no longer used.
  • gxConfig objects no longer accept untyped data through gxListB::Add(void *).
  • Rebuild the index files of RDBMS tables that have BLOB fields and an all-field key ("PRI: COL NONE").
  • Programs that walk gxsXML trees loaded from documents with mixed content should skip nodes with an empty name, or handle them as text.
  • A thread pool is now cleared by stopping its running joinable threads. Threads must reach a cancellation point, and the gxThread object must still exist when the pool is cleared or deleted.
