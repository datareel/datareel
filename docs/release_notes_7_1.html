DataReel 7.2 followed on the same day with the journal, the page cache and faster I/O; see RELEASE_NOTES_7.2.txt.

DataReel 7.1 is a beta release. DataReel 7.4.1 (11/20/2026) is now the stable release, and DataReel 6.4.2 the legacy release (bug fixes and security updates only); please report problems through https://datareel.com/contact.php.

DataReel is an object database (OODB) and cross platform communications toolkit for C++. 7.1 removes the gxRDBMS relational tables so the library is made of its two parts: the object database (gxDatabase, gxBtree, POD, InfoHog and the database utilities) and TLS networking. Everything else is unchanged from 7.0; see RELEASE_NOTES_7.0.txt for the move from 6.x to DataReel 7.

The library version is 7.1 (version.txt, DATAREEL_VERSION_STRING in gxdlcode.h, libdatareel.so.7.1). The shared library soname (libdatareel.so.7) and the database file format version (gxDatabaseVersionNumber 4630) are unchanged, and find_package(DataReel 7) finds 7.1.

Removed, and what to use instead

 gxRDBMS relational tables        An embedded SQL database
 (gxrdbms.h, gxrdbhdr.h,
 gxrdbdef.h), db_rdbms example
  • The 18 gxRDBMS error codes in gxDatabaseError (gxDBASE_BAD_TABLE to gxDBASE_ILLEGAL_CHAR) are kept as gxDBASE_RESERVED_1 to gxDBASE_RESERVED_18, with the message "Database exception: Reserved error code", so the values of the other codes do not change. Code that named the old constants must drop them.
  • CDate stays as a portable 4-byte date type.

File formats

Database, index and InfoHog files are unchanged and are byte-for-byte identical to the files 7.0 and 6.2 write. gxRDBMS table files can no longer be opened; read them with 6.2 or 7.0 and move the data to an embedded SQL database.

How the release was tested

  • tests/run_tests.sh on RHEL 10.2: 40 checks (the 42 of 7.0 less the two gxRDBMS checks) passed in the default 32-bit native type build and in a 64-bit engine, portable type build, with no compiler warnings.
  • Open Stock Analysis and Open Crypto Analysis built against 7.1 with no warnings; the OSA read_trend_forecast parity test gave identical output to the 7.0 build in all 51 cases.
