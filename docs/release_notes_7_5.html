DataReel 7.5 adds the datareel Python module, a package that installs with pip. It is built from this repository (python/) on top of 7.4.1, so everything in 7.4.1 is in it (RELEASE_NOTES_7.4.txt, "NEW IN 7.4.1"). The file formats and the gxStream and gxObjRepl wire formats are those of 7.4.

NEW IN 7.5 BETA 3 PATCH 1 (tag 7.5-beta3-patch1, 11/21/2026)

  • index_check / objrepl ixcheck take index names only ("rt_day", looked up in the node's .def files) or none (every index the node has). A spec that names no index of the node, or that cannot be read, is a usage error with its own message (IndexCheck returns 64; Python raises datareel.Error), no longer "bad index", which looked like a damaged index (reported from OSA, 11/20).
  • datareel.Database(path, create=True, static_size=N): the static area of gxDatabase::Create(fname, static_size) from Python, with read_static(offset=0, size=-1), write_static(data, offset=0) and the static_size property (asked for by OCA, 11/20). Bounds checked; journaled like any write when the file is attached to a Journal.

New in 7.5 beta 3

  • The incremental rejoin (gxObjRepl, C++ and Python): when both nodes wrote after a split (a standby took over while the old primary kept writing, the OSA emergency path), objrepl rejoin / datareel.rejoin() keeps the old primary's data and the list of objects its unacknowledged commits changed. The new primary checks that the two histories match at the seq it took over at (ROOT/epochs, written at each takeover) and sends only the objects either node changed since then (its change list, ROOT/objrepl.changes.gxd), then its digest log past the split: equal digests, with no full send. A full send instead when the histories differ, when the change set is more than rejoin-max-share percent of the objects (default 50), or with objrepl rejoin --full / datareel.rejoin(root, incremental=False). A node killed in the middle keeps waiting and finishes on the next connect.
  • The schema check: a fingerprint of the index spec, the link map and the new "schema" setting (the application's record layout version, such as news-v3) goes with the hello. An incremental rejoin between nodes whose fingerprints differ is refused, with what differs; the node keeps its data and is rebuilt instead: a new copy in an empty folder takes a full send, then objrepl swap OLD NEW / datareel.swap(old, new, index) puts it in place and keeps the old folder as OLD.before-rebuild-DATE (gxObjRepl::Swap). In the running stream a difference is a warning.
  • Status: last_rejoin (incremental or full send) and last_rejoin_objects on the primary. objrepl: --schema, --rejoin-max-share, --drain-secs (the generator's final drain).
  • Wire: new fields at the end of the hello and its reply, and frames F_RJ_SET, F_RJ_BATCH and F_RJ_END. 7.4.1 and 7.5 beta 2 nodes work with beta 3 nodes as before (tested both ways).
  • Tests: utils/objrepl/test_objrepl_rejoin.sh (the emergency path and back, the schema refusal, rebuild and swap, another history, the share limit, --full, a node killed inside a batch and inside the end, and with OBJREPL_OLD_BIN a 7.4.1 node both ways), and Python tests: a C++ production primary and a Python DEV copy that detaches and writes, the rejoin and the roles going back; a Python primary under a C++ new primary; the schema refusal, rebuild and swap from Python.
  • Package version 7.5b3 (patch 1: 7.5b3.post1); library version "7.5 beta3" (patch 1: "7.5 beta3-patch1").

New in 7.5 beta 2

  • Writes from Python: datareel.Primary(root, config=None, settings=None, quiet=False) opens a node as a gxObjRepl primary in the Python process: open_database, begin, commit, rollback, transaction() (commit, or rollback when the block raises), new_id, put, remove, purge, pump, drain, and the primary's reads (get, is_live, ids, databases, find_key, nearest); last_seq, epoch, copy_applied. Settings are the objrepl.conf keys, as a dict or a file. Calls release the GIL.
  • Tests: Python writes checked by the C++ reader and objrepl ixcheck, transactions and rollback, refusals (a copy's folder, a node another writer holds, bad settings), a Python primary killed with KILL and reopened, and replication from a Python primary to a C++ copy with equal digests. Examples 10 (write objects) and 11 (an event log with a rolled back batch and a copy) in python/examples, run by the tests.
  • Node folder tools: datareel.status(root), datareel.digest(root, links=""), datareel.takeover(root), as the objrepl tool's status, digest and takeover. With takeover(), DEV makes a standalone test node from a file copy of a stopped copy and writes it from Python, while it only reads the production nodes (user's manual, section 5a).
  • Replication from Python: datareel.Copy (serve() until stop(), the reads, applied_seq, in_snapshot), rejoin(), check(), clear_alarm(), index_check(), and address_of()/id_at() for link fields. Tested with both nodes in Python: drain, equal digests, a takeover and a rejoin.
  • The database layer from Python: Database (gxDatabase block files), BTree (gxBtree index files of KEY_SIZE-byte keys and an 8-byte value; BTree(path, 32) reads a gxObjRepl index file), Journal (gxdJournal transactions over attached files; datareel.transaction(journal)), and vector index writes: create_vector_index(), VectorIndex(path, write=True) insert/update/delete/repair/verify, merge_vector_indexes(). A Python writer killed mid-transaction leaves whole transactions.
  • gxStream from Python: Stream (a TLS client), StreamServer (mutual TLS), ObjectClient (the object server's object service: add, request, change, delete, addresses, vector_info, vector_search). object_server takes --vectors FILE. Tested against C++ objrepl and object_server.
  • Examples 12 (block file and B-tree in journal transactions), 13 (vector day files and a merge) and 14 (a Python primary and copy, a failover and a rejoin).
  • From the OSA beta 2 handoff: Reader.ids(db, after=, limit=) pages a large database from the id index (gxObjReplReader::IdsAfter), so a walk never holds the read lock long; Reader.find_range(index, lo, hi=None, limit=0) (gxObjReplReader::FindRange) for B-tree key ranges; Reader(root) with no spec reads the node's .def files, and Reader.index_spec shows it; the "lock-wait" setting (gxObjReplConfig::lock_wait, C++ default 5 s, Python default 0, so a held root fails at once); datareel.Node(root, config, role=), datareel.detach(root), and seq/role on Primary and Copy. Primary and Copy ids() take after= and limit= too.
  • More tests: a C++ primary to a Python copy (a full send to a new copy, incremental after a restart, and a copy killed with KILL while it applies, restarted and caught up: equal digests, ixcheck, the C++ final check), C++ and Python writers taking turns on one folder, and a Reader while a Python writer commits.
  • Package version 7.5b2; library version "7.5 beta2".

New in 7.5 beta 1

  • python/: the datareel package (version 7.5b1). Read only in this beta:
    • Reader(root, index=""): a gxObjRepl node folder read from another process while the node runs (gxObjReplReader, 7.4.1): get, is_live, ids, databases, find_key, nearest, refresh, and the seq, epoch and role of the commit read. Whole commits only.
    • VectorIndex(path, spec=None): a .vix file read only: search (with tag filters, exact or graph), get, dim, count, spec, metric.
    • BlockFile(path): a .gxd file read only: addresses() and read().
    • Query vectors as lists of numbers or float32 buffers (array('f'), numpy float32). Calls that read files release the GIL.
  • The extension uses the plain CPython C API: no third-party packages to build or to run. setup.py builds it with CMake (python/ CMakeLists.txt), with the DataReel library inside it (static, the 64-bit engine); it links the system OpenSSL 3.
  • Tests: python/tests/run_python_tests.sh builds the wheel and the C++ test programs, installs the wheel in a throwaway virtual environment and runs python/tests/test_datareel.py: a node written by the C++ library read through every call, readers in Python threads while a C++ primary writes 2000 commits and while a copy applies 800, the node's vector index file and a block file. Built on RHEL 9 (UBI 9, CPython 3.12); the same wheel passes on RHEL 10.

Limits of beta 3

  • An incremental rejoin holds the new primary's lock while it sends (capped by rejoin-max-share).
  • Not wrapped: InfoHog and POD persistent objects, the 6.x-style gxStream block requests, and the network clients Python's standard library has (HTTPS, SMTP, POP3, IMAP, FTPS).
  • The 64-bit database engine only.
  • Linux x86_64, CPython 3.12. Windows wheels are not built yet.

Planned for later 7.5 betas

  • Windows wheels.
